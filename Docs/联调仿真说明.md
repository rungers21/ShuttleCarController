# 联调仿真说明（上位机 ⇄ Modbus 从站仿真器）

本说明对应当前代码：上位机工具 `ShuttleCarController` 与仿真从站 `ShuttleCarSimulator`。
默认二向穿梭车协议画像 `TwoWayShuttleProtocolProfile` 仍以 `ShuttleCarController\Services\ProtocolMap.cs`
中的地址映射为唯一来源；新增车型通过 `IDeviceProtocolProfile` 扩展，不需要改通信客户端。

> 重要：`ProtocolMap` 是按方案 4.3 规则推导出的**联调映射**，不是硬件方确认的最终协议
> （方案 P0-02～P0-07 仍未关闭）。接实车前必须按确认后的地址、字节序、位定义替换该文件。

## 1. 启动方式

1. 编译整个解决方案：`dotnet build ShuttleCarController.slnx`
2. 启动仿真从站（监听 `127.0.0.1`）：
   - 运行 `ShuttleCarSimulator\bin\Debug\net10.0-windows\ShuttleCarSimulator.exe`，
   - 端口默认 `15020`、站号默认 `1`，点击“启动服务”，状态栏显示“Modbus TCP 从站运行中”。
3. 启动上位机 `ShuttleCarController.exe`，在左侧 Modbus 区填写：
   - IP `127.0.0.1`、端口 `15020`、站号 `1`；
   - 轮询起始地址 `0`、轮询数量 `38`（覆盖全部三个数据区）；
   - 点击“连接”。

连接成功后“数据新鲜度”应显示约 0.5 s 内的正常数据，“参数解析”和“数据表”出现实时值，
日志中出现“Modbus TCP 连接成功”。

4. 自动化验证（无需打开窗口）：

```powershell
dotnet build ShuttleCarController.slnx -c Release
dotnet test ShuttleCarController.slnx -c Release
```

测试工程 `ShuttleCarController.Tests` 覆盖协议编解码、冲突检测、配置恢复、快照帧缓存、
日志后台落盘、ViewModel 联锁/筛选，以及在回环端口启动真实仿真从站的端到端任务闭环、
故障注入、写失败 `ResultUnknown` 与断线重连。

## 2. 地址映射

三个数据区放在同一地址空间，整体随“轮询起始地址”平移：

| 数据区 | 寄存器范围（相对轮询起始地址） | 对应 DB 字节 |
|---|---:|---:|
| 车辆→上位机 | 0～19 | 0～39 |
| 上位机→车辆 | 20～30 | 0～21 |
| 上位机交互 | 32～37 | 0～11 |

换算规则（方案 4.3）：

```text
寄存器索引 = 轮询起始地址 + 区偏移 + DB 字节偏移 / 2
寄存器内位序号 = (DB 字节偏移 % 2) * 8 + 位偏移
Int 占 1 个寄存器，DInt 占连续 2 个寄存器（高字在前）
```

完整字段清单（名称、DB 偏移、类型、位号）见 `ProtocolMap.Fields`，数据表会逐条显示。

## 3. 仿真从站的行为

| 触发 | 仿真从站动作 |
|---|---|
| 命令区任务号变化 | 回显任务号、出库方式、车体方向；进入运行；位置每 250 ms +1；3 s 后自动置“任务完成”位和 Int@2=1，清除出入库未完成 |
| 确认完成 Bool@20.0 | 清除状态区任务号、完成位、出入库未完成，回到待机 |
| 清除异常 Bool@20.1 | 清除全部故障位（2.0～3.6）和报警码，恢复“正常”位 |
| 盘点清零 Int@2 | 从站回零，镜像位 `0.1` 置位 1.5 s |
| 初始化 Int@10 | 从站回零，置“小车启动完成/待机”位，车辆状态回 0 |
| 电量 | 启动 100；任务运行期间每 10 s −1，≤20 自动置“电量不足”故障位 |
| 界面按钮 | “模拟任务完成”立即完成当前任务；“清除所有故障”；“设置电量”；“设置报警码” |

故障开关直接对应交互区的位字段，勾选后上位机下一次轮询即可看到报警明细与报警码。

## 4. 上位机侧的命令握手

| 命令 | 写入 | 判定 |
|---|---|---|
| 下发任务 | FC16 写命令区 20～28（9 个寄存器） | 等待状态区回显同一任务号，超时返回“结果未知” |
| 确认完成 | 读—改—写命令标志位 `20.0`，等 200 ms 复位 | 等待状态区任务号和完成位清零 |
| 盘点清零 / 初始化 / 清除异常 | 写 1，200 ms 后写 0 | 发送即返回“已接收”，结果以最新快照为准 |

等待窗口为 `max(1500 ms, 3 × 请求超时)`。任何写入超时都返回 `ResultUnknown`，界面禁止自动重发，
必须由操作人员核对车辆状态。软件联锁（数据新鲜、无报警、无活动任务）在 `MainWindowViewModel` 中检查。

## 5. 界面降噪与筛选

- “基础控制 / Modbus 原始读写”收进默认折叠的工程调试 `Expander`，首屏保留任务控制、参数解析和关键数据。
- 参数解析区无活动报警时只显示绿色“无活动故障”；有报警时才展开活动故障明细（含 A/B 侧、有货/无货、FIFO/FILO 冲突项）。
- 数据表支持按字段名、DB 偏移、Modbus 地址搜索，按数据区下拉过滤，以及“仅看非零”“隐藏备用字段”开关。
- 日志区可按“全部 / 仅警告与错误 / 仅错误”过滤，可暂停自动滚动；“清空”只清界面列表，不删除磁盘日志。
- “重置本地任务”用于车辆外部复位或切换连接后解除本地任务锁：二次确认后只清除上位机 `ActiveTaskNumber`，
  **不向车辆写任何数据**；执行前必须人工核对实车状态。

## 6. 设备协议扩展

- `IDeviceProtocolProfile`（`ShuttleCarController\Services\Devices`）定义轮询长度、字段/故障映射、
  `Decode`、`EncodeCommand`、命令达成判定；默认实现为 `TwoWayShuttleProtocolProfile`。
- `DeviceWriteStep` 把命令描述为“写寄存器 / 置位 / 复位 / 延时”的步骤序列；通信层不再硬编码寄存器偏移。
- `ModbusShuttleCarClient` 构造时注入画像，轮询解码、命令编码、握手等待全部走画像。
- `DeviceDescriptor` 描述设备 ID、类型、画像与连接；`IDeviceClientFactory` 按画像标识或描述创建客户端。
- 配置项 `DeviceProfileId`（`%LOCALAPPDATA%\ShuttleCarController\config.json`，默认 `two-way-shuttle`）
  在启动时选择画像，修改后重启生效；未知标识回退默认画像并写调试跟踪。
- 新增车型：实现 `IDeviceProtocolProfile`，在 `DeviceProfileCatalog.Profiles` 登记，并在工厂/配置中使用其 `Id` 即可，
  不需要修改 ViewModel 或传输层。`ProtocolMap` 仅作为默认画像的向后兼容门面保留。

## 7. 已验证的联调项

在仿真从站上跑通的端到端自检（28 项）：

- 连接、轮询解码（电量/车号/连接状态/位置/A、B 侧/货物位）、数据表 74 行；
- 下发任务 → 任务号回显 → 3 s 自动完成 → 确认完成 → 任务清零；
- 注入“A侧急停”故障 → 报警码与故障明细出现 → 清除异常 → 报警消失；
- 盘点清零、初始化、非法任务号拒绝；
- 停止从站 → 工具进入重连并保留上一次数值（降级为错误质量）→ 从站重启后自动恢复。

## 8. 接实车前必须确认

- P0-01 通信制式与网络参数；P0-02～P0-07 区基地址、功能码、地址起始值、字节/字序、位映射；
- P0-08 任务类型、出库方式、车体方向数值编码（当前 `ProtocolMap` 里的 FIFO=0/FILO=1、A面=0/B面=1 只是仿真约定）；
- P0-10 任务握手时序；`20.0/20.1` 采用脉冲还是电平复位；
- 确认后替换默认画像中的地址与枚举显示（`ProtocolMap` / `TwoWayShuttleProtocolProfile`），并重新跑一遍第 7 节联调项与
  `dotnet test ShuttleCarController.slnx -c Release`。
